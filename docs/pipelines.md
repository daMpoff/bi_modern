# Как выполняется конвейер

## Граф и источники

Перед чтением источников движок строит план графа. Один порядок обхода используется и для выполнения, и для расчёта происхождения данных. Проверка отклоняет циклы, повторяющиеся идентификаторы, ссылки на отсутствующие узлы, неверное число входов и несколько выходов. [Построение плана](../api/execution/graph_plan.py)

В блоке JOIN порты `left-target` и `right-target` определяют стороны соединения. Графы, сохранённые без портов, используют прежний порядок до следующего сохранения в редакторе. В обоих движках одноимённые колонки справа получают суффикс `_right`, включая ключ соединения. Строки с пустыми ключами между собой не соединяются.

Формулу можно сохранить в полях `outputField` и `expression` или в прежнем списке `formulas`. Например, выражение `price * $rate` умножает значение колонки на параметр запуска. Выражения разбираются через AST.

Для SQL-источников движок по возможности переносит соседние фильтры и агрегации в запрос целиком. Остальные операции выполняются в конвейере. При расчёте точных счётчиков происхождения данных все операции проходят через движок. Ошибка чтения источника возвращается как ошибка запуска.

## Результат и фоновые задачи

Клиент сохраняет метаданные ответа для таблиц предпросмотра и графиков. Поля `rows_count` и `columns` описывают выборку, `result_set_id` связывает последующие запросы с конкретным запуском, а `error` содержит ошибку. Если сохранение графа завершилось ошибкой, редактор останавливает запуск.

Каждый результат привязан к пользователю, пайплайну и идентификатору запуска. Время хранения выборки — 10 минут. При Django-кэше `locmem` или `dummy` процессы одного хоста обмениваются результатами через `virtual_env/cache/bi_modern_execution`. Для API и Celery на разных машинах настройте общий кэш, например Redis. Статус задачи доступен инициатору, пока ему принадлежит пайплайн. [Реализация кэша](../api/execution/result_cache.py)

## Интеграция с ядром

| Контракт | Значение |
| --- | --- |
| Модуль и очередь Celery | `bi_analysis_modern` |
| Схема PostgreSQL | `m_bi_analysis_modern` |
| Префикс REST API | `/api/bi_analysis_modern/` |
| Маршрут списка дашбордов | `DashboardsModern` |
| Ключ API в общем реестре клиента | `biModern` |

Обычный BI и BI Modern могут работать одновременно. Для Vue-кода модуля используйте его объект `biEndpoints.bi`, для кода ядра — запись `biModern`. Формы загружают файлы через `apiClient.post` с `FormData` и получают списки через `apiClient.get`.

При создании подключения PostgreSQL форма отправляет `connector_type: postgres`. При редактировании форма читает тип из подключения. Переименование сохраняет конфигурацию, а частичное обновление меняет только переданные поля.
